1. fetch() Error Handling

A common beginner mistake is:

const response = await fetch("/api/users");

const data = await response.json();

Many beginners think a 404 or 500 automatically enters catch.

It doesn't necessarily.

You should check:

const response = await fetch("/api/users");

if (!response.ok) {
    throw new Error("Request failed");
}

const data = await response.json();

A proper pattern:

async function getUsers() {
    try {
        const response = await fetch("/api/users");

        if (!response.ok) {
            throw new Error("Failed to fetch users");
        }

        const users = await response.json();

        console.log(users);

    } catch (error) {
        console.log(error.message);
    }
}

getUsers();
Industry use

Almost every frontend application communicates with APIs.

You need to handle:

200 → Success
400 → Bad request
401 → Unauthorized
403 → Forbidden
404 → Not found
500 → Server error
2. HTTP Headers

Headers contain additional information about a request or response.

Example:

const response = await fetch("/api/users", {
    headers: {
        "Content-Type": "application/json"
    }
});

For POST:

const response = await fetch("/api/users", {
    method: "POST",

    headers: {
        "Content-Type": "application/json"
    },

    body: JSON.stringify({
        name: "Param",
        age: 20
    })
});

Industry use:

Authorization
Content-Type
Accept
Cache-Control
3. AbortController

Suppose a user searches:

p
pa
par
para
param

You don't want five unnecessary requests continuing forever.

You can cancel a request.

const controller = new AbortController();

fetch("/api/users", {
    signal: controller.signal
});

controller.abort();

Real-world use:

Search suggestions
Page navigation
Request cancellation
Preventing unnecessary network work
4. Debouncing

Suppose a search box triggers an API request every time the user types.

Bad:

P → API
Pa → API
Par → API
Para → API
Param → API

Instead, wait until the user stops typing.

let timer;

function search(value) {

    clearTimeout(timer);

    timer = setTimeout(() => {
        console.log("Searching:", value);
    }, 500);
}

This is debouncing.

Industry use

Search:

Amazon
Google
LinkedIn
YouTube

etc.

8. Cookies — Important Security Concept

For authentication, secure cookies can be configured with:

Secure

HttpOnly means JavaScript cannot directly read the cookie.

That helps reduce some token-theft risks from XSS.

For serious authentication systems, don't blindly store sensitive authentication tokens in localStorage.

Never trust user input.

22. Big-O

You should understand basic complexity.

typically involves a linear scan:

O(n)

A hash-based lookup such as:

map.get(id)

is typically:

O(1) average

This becomes very important when datasets become large.

23. Memory Leaks

A memory leak happens when your program keeps references to things it no longer needs.

Browser example:

const handler = () => {
    console.log("clicked");
};

window.addEventListener("resize", handler);

If a component is removed but its listener remains unnecessarily attached, it can contribute to memory problems.

Cleanup:

window.removeEventListener("resize", handler);

In React, this becomes especially important with effects and subscriptions.

25. Don't Repeat Yourself — DRY

Bad:

const total1 = price1 * 0.18;
const total2 = price2 * 0.18;
const total3 = price3 * 0.18;

Better:

function calculateTax(price) {
    return price * 0.18;
}

Then:

calculateTax(price1);
calculateTax(price2);
calculateTax(price3);
26. Single Responsibility

Bad:

    // generate invoice

validateUser()
saveUser()
sendEmail()
generateInvoice()
sendNotification()

This idea leads into SOLID and architecture.
